## 2. `t` — 判定の手順

`trackTypeForTrack:seqID:ginst:inSong:`（`0x01693e90`）の入力は、トラックエントリ *E*（0x50 バイト。種類 +0x10、深さ +0x12、フラグ +0x14、ID +0x20）、`seqID`、`ginst`、曲である。

**ginst オブジェクト *G*。** 最初に `FUN_01a15c7c(曲, ginst, NULL)`（`0x01693ebc`）を呼ぶ。これは、`ginst` が選ぶストリップの種類バイト（+0x69）が **0x11** で、分類バイト（+0x335）が 13 未満のときだけ、曲側の表を引いて *G* を返す。それ以外は NULL。*G* の先頭の `ushort` から bit 3 を除いた値を「種別語」と呼ぶ（`and #0xfffffff7`）。名前の `ginst` は Logic 内の用語（`gindex` と同じ語源。**推測**: generic instrument）。

**`/ati` が渡す引数。** *E* はトラックエントリ、`seqID` はストリップの `folder`（`BgTrackInfoTrackIDKey` の上位 16 ビット）、`ginst` は `n.gindex` と**同じレジスタの値**（`/gtFaderData` の `g` のキーと同じ。アンカー `TT-callsite`、`CB-gindex`）、`song` は曲。`/sti` のブロックは *E* を渡さず、`ginst` に選択中のストリップの添字を渡す（§3）。

**シーケンス *Q*。** `seqID` が 0x7ffffff8 または 0x7ffffffc のときは別の配列（+0x318）の要素、それ以外は 4 の倍数の通常 ID で配列（+0x228）を引く。*Q* の +0x30 の bit 0 が立っていると無効として扱う。*E* が渡されなければ、*Q* の中から `ginst` と同じ ID（+0x20）を持つエントリを探す。

**規則。** 上から順に試し、最初に当たったものを返す。

| 規則 | 条件 | 値 |
|---|---|---|
| R1 | *E* と *Q* が分かり、`FUN_019fa680(E, Q)` が真。真になるのは、*E* の種類が 3・4・5・0xc 以外で、*E* の後ろにある「種類が 5 でも 0xc でもない最初のエントリ」の深さがちょうど *E*+1 のとき | *E* の +0x14 の bit 6（0x40）が立てば **7**、立たなければ **8**。内部の整合が取れないときも 8 |
| R2 | *G* があり、種別語が `0x44` | **5** |
| R3 | *G* があり、種別語が `0x46` | 符号付き `short` の *G*[+2] が正なら **10**、そうでなければ **6** |
| R4 | *E* が分かり、*E* の種類が 4（種類 0xc は直前の「0xc でも 5 でもない」エントリの種類を使う）。または、種類 3 で子を持つ *E* の親エントリが種類 4 | **3** |
| R5 | *G* があり、種別語が `0x40` なら **1**、`0x43` なら **2** | 1 / 2 |
| R6 | *E* が分かり、*E* の ID（+0x20）が選ぶストリップの種類バイトが 0x13 未満で 0x11 でない | **4** |
| R7 | *G* があり、種別語が `0x42` | **9** |
| R8 | どれにも当たらない | **0** |

*E* が分からないとき（*Q* の中にも見つからないとき）は R4 と R6 が飛ばされる。戻り値は `char` として符号拡張される。根拠の命令は、アンカー表の `TT-*`・`GI-*`・`PT-*` の行。

**副作用（静的に確認）。** *E* の次のエントリが 2 段以上深いとき、この関数は *E* の深さ（+0x12）をそのエントリの深さへ書き換える（`0x01694040`、`0x019fa708`）。読み取りのはずの呼び出しが、Logic 内部の表を整える。`/ati` を作るたびに起こりうる。影響は未確認。

### 2.1 意味の手掛かり（仮説）

| 手掛かり | 何が分かるか |
|---|---|
| `updateSelectedTrackInfo`（`0x0168e754`）は、単独選択で *G* の種別語が `0x44` のとき、名前に `cf_MasterTrack`（`0x02338f08`。実際の文字列は「Master Track」）を使う | 当初は「種別語 `0x44` は Master」と推測した。**受信では 0x44（`t = 5`）は Stereo Out だった**。トラック領域の「マスタートラック」が Stereo Out を表すため、と考えると矛盾しない |
| `ginstNeedsMidiClipType:` は、種別語が `0x42` のとき真を返す。`pluginsForTrack:isMIDI:` も `0x42` を見る | 種別語 `0x42` は MIDI で動く種類（`t = 9`）。当初は「ソフトウェア音源」と推測したが、**受信ではソフトウェア音源は 0x43（`t = 2`）だった**。0x42 が何か（外部 MIDI など）は未確認 |
| `importChannelStripWithGInstID:` は `(種別語 \| 2) == 0x46` で `0x44` と `0x46` をまとめて扱う | **受信で 0x46 = Master（`t = 6`）、0x44 = Stereo Out（`t = 5`）**。出力と Master をまとめて扱う、と読める。*G*[+2] が正のときの `t = 10` は、VCA など Master 以外の同種のストリップと推測（**仮説**、確信度: 低） |
| `createBusWithDestinationInstrument:…` は種別語 `0x45` を見る | `0x45` はバス。`/ati` の `t` の規則には現れず、R4 の後は R6 か R8 へ進む |
| 種類ごとの既定色（§4）で、キー 3 だけが別の番号（76） | `t = 3` は他と異なる扱い（フォルダー系の仮説。確信度: 低〜中） |

専用プロジェクトの内訳（Logic の画面で確認）は、ソフトウェア音源 3 本（Piano・Bass・Synth）、オーディオ 7 本（Audio・Trk05〜Trk10）、出力（St Out）、Master である。§7 の予測はこの内訳に基づく。

**受信で分かった対応**（[EXP-REMOTE-001](../experiments/EXP-REMOTE-001-receive-initial-state.md)）：オーディオ 7 本 = `t` 1、ソフトウェア音源 3 本 = 2、Stereo Out = 5、Master = 6。規則 R2・R3・R5 は静的な読みどおりに働き、外れたのは種別語の意味の推測だけだった。

## 3. `/sti` の `t`

ブロック `FUN_01696598`（`0x01696598`）が、選択中のストリップごとに `trackTypeForTrack`（*E* は NULL）を呼ぶ。結果が **1〜4** のときだけ、共有の 1 バイトに反映する。

- バイトが 0 なら、結果を入れる。
- バイトが結果と同じなら、そのまま。
- バイトが結果と違えば、**2** にする（混在）。
- 結果が 0 または 5 以上なら、バイトは変えない。

選択が無い、あるいは 1〜4 の結果が無いときは 0（何も選択していないときに送る `t` は定数 `0x0242fcd0` = 0。キーとの対応はデコンパイラ出力のスタック変数の並びによるもので、機械語では未確認。アンカー `ST-none-*`）。したがって `/sti` の `t` は 0〜4 で、**結果が 5 以上のストリップ（ソフトウェア音源 9・Master 5・出力 6/10・親トラック 7/8）は数えられず、それだけを選ぶと 0 のまま**である。1〜4 のストリップと一緒に選んでも、数えられるのは 1〜4 のほうだけである（静的事実。アンカー `ST-block`）。

## 4. 種類ごとの既定色

`/colorIndexMap` を作る `createColorDataDictionary`（`0x00a69960`）は、`defaultColorIndexForTrackTypes` として次の 5 組の辞書を入れる。

| `t` のキー | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 既定の色番号 | 9 | 16 | 9 | 76 | 9 |

キーは 0〜4 だけで、`/sti` の `t` と同じ範囲である。キーと値の対応は、機械語のスタック配置と `dictionaryWithObjects:forKeys:count:` の引数順（`x2` = 値、`x3` = キー）で確認した（アンカー `DC-*`、`SEL-dictionaryWithObjects`）。**色番号の意味（どの色か）は未解決**。

## 5. `c` — 4 バイトの並び

ストリップごとの色番号は、ストリップの +0x85 の符号付きバイトである（`0x01697120`）。

| キー | 作り方 | 4 バイト |
|---|---|---|
| `nc`（Normal） | `FUN_00d34de8` が色番号から（色相、2 つのバイト）を出し、`FUN_017e5998`（HSV→RGB）に **アルファ 1.0** を渡す | R, G, B, A |
| `sc`（Selected） | `FUN_00d35578(番号, 40, 100)`。色相は番号から、彩度 0.40、明度 1.00。静的領域 `0x026c6de0` に R, G, B, 1.0 を置く | R, G, B, A |
| `tnc`（IconTintNormal） | `FUN_00d358a0(番号, 4)` が `NSColor` を作り、`FUN_006d874c` が `getRed:green:blue:alpha:` で読む | R, G, B, A |
| `tsc`（IconTintSelected） | `FUN_00d358a0(番号, 2)`、あとは `tnc` と同じ | R, G, B, A |

詰め方は 4 色とも同じ（`0x01697144`〜`0x0169716c` など）。4 つの倍精度値に 255.0 を掛け、`fcvtzs`（**ゼロ方向への切り捨て**。0.999 は 254）で整数にし、`uzp1`・`xtn`・`uzp1` で各下位 1 バイトを取り出して `str s0` で 4 バイトを書く。順序は倍精度値の並び（R, G, B, A）のままである。

- `FUN_017e5998` は R, G, B を `d0`〜`d2` に、**入力のアルファを `d3` にそのまま**返す。第 1 色のアルファは 1.0 なので、4 バイト目は 0xFF。
- 色番号 −1 と 0 は、`FUN_00d34de8` ではパレットの 9 番目に当たる（`0x00d34e58`）。`tnc`・`tsc` では、`FUN_00d358a0` が定数（色相 212、バイト 55 と 100、アルファ 1.0）を使う。
- **計算値（捕捉した値ではない）:** その定数を `FUN_017e5998` の補正表（画像内の `0x01d434f8`・`0x01d44038`）で計算すると **`8c c0 ff ff`**（R 140、G 192、B 255、A 255）。色番号が −1 か 0 のストリップの `tnc`・`tsc` で一致するはずである（[`remote_colour_model.py`](../../Tools/research-scripts/remote_colour_model.py)）。
- 色番号が 1 以上の `nc`・`sc` は、パレット（`FUN_00d34de8`）が実行時に設定値から組み立てる表を使うため、**静的には値を出せない**。`tnc`・`tsc` の番号 1 以上は `MASharedInstrumentIconService` の `tintColorWithHue:withModifier:mode:` の結果で、これも未解析。

## 9. 同じ呼び出しの `nc` と `p`（追記）

`/ati` の同じブロックで作る `nc` と `p` の 2 列も、*G*（`FUN_01a15c7c` の戻り値。スタックの `sp+0x80` に保存される。アンカー `NC-src`）から読んでいる。

| 列 | 値 | 条件 |
|---|---|---|
| `nc` | 表 `0x01d59030` の *n* 番目（*n* = *G*[+0xd4]、1〜15）: 1, 2, 4, 4, 6, 7, 8, 8, 8, 8, 10, 10, 12, 14, 16 | *G* があり、*n* が 1〜15 |
| `nc` | 0 | *G* が無い、または *n* が 0 か 16 以上（定数 `0x0242fcb8` = 0） |
| `p` | `0`、`-5`、`-1`、`-4`、`-1`、`-4`（*k* = 0〜5） | *G* があり、`allowedElementsForStrip:` の bit 27 が立ち、`FUN_01a2cc68(G, 0)` の結果 *k* が 6 未満（64 ビット定数 `0xfcfffcfffb00` の第 *k* バイト） |
| `p` | `-1` | 上の条件を満たさない *G*。または *G* が無く `t` が 4 でない（定数 `0x0242fce8` = −1） |
| `p` | `0` | *G* が無く `t` が 4（定数 `0x0242fcd0` = 0） |

**以前の読みの訂正:** SA-REMOTE-STATE-001 は `nc` を「曲の +0xd4 のバイト」としていた。デコンパイラが `FUN_01a15c7c` の戻り値を捨てたように表示し、同じ変数名を曲にも *G* にも使っていたための誤読で、機械語では `str x0,[sp,#0x80]` で保存した値（*G*）を後で読んでいる。値の並び（1, 2, 4, 4, 6, 7, 8, …, 16）は、サラウンド形式ごとのチャンネル数に見える（**仮説**、確信度: 中）。`FUN_01a2cc68` の結果 *k* の意味は未解決。
