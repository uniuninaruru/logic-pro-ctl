## Version classification: P019-01–04

`DfDocument` owns the **class method** `checkSongVersionForSongAtURL:`. It obtains the input URL's path and retains a URL lock. A non-directory input returns 3. If the `Alternatives` component exists as a directory, it returns 4 through the normal unlock path, without reading native `ProjectData` beneath `Alternatives`. The branch is a classifier; the meanings of 3/4 are unknown. (P019-01)

Only when there is no `Alternatives` directory does it append the literal lowercase `projectData`. Existence and a non-directory low-bit condition gate `NSData` reading with options1 and errorNULL. Nil data, zero length, nil unarchiver initialization or a missing `Version` key produce 3. These bodies contain no raw magic comparison. This archive route does not establish the native uppercase `ProjectData` header or schema. (P019-02)

`initForReadingFromData_ma:error:` receives the actual allocated `NSKeyedUnarchiver`. When `DfDocumentSystem` exists, `decodeObjectOfClass:forKey:` receives the `NSString` class; the returned object is retained and released on normal cleanup, without a content comparison. `Version` presence and its decoded integer are preserved. `CbVersion` is also decoded when present, but its result is discarded. After `finishDecoding_ma`, `Version` presence selects `checkDocumentVersion:currentRunningVersion:` on the `DfDocument` class with `(decodedVersion,55000)`, and the method returns that call's actual integer. The comparator body is unread; 55000 is an observed immediate, not proof that the current native format is accepted. Decoded runtime types, exceptions and complete ownership remain unverified. (P019-03–04)

## Load wrapper: P019-05–12

`CLgSongDocument` owns the **instance method** `_readLogicXProjectFromURL:error:`. It sends `copyDeepMutableMA` to the original project information and passes new `infoDictionary` to `_setProjectInformation:error:`. Nil new information returns false and stores Cocoa259 only when `errorOut` is non-NULL. Setter result w0 zero also returns false, with no explicit old-info restoration on that branch. Getter, setter and copy internals are unread. (P019-05)

After metadata setup, it calls `_migrateARAFilesFolder:error:` without branching on the result. If `mAlternativeToLoad` (an 8-byte `q` field at self+48) is not −1, it sends `setActiveVariant:` and resets the field to −1. This wrapper has no explicit rollback of that variant change or field reset after later failure; runtime effects and complete rollback behavior are unknown. (P019-06)

It obtains `projectDataURL(createDirectories=false)`, appends `bak`, and calls `move(bak,main,errorOut)` only when backup exists and main does not. A zero success bit restores old project information and returns false. After a successful move, it derives a metadata backup by deleting the metadata URL's extension and appending `bak`, then moves that backup to metadata with errorNULL and ignores the result. URL getters and native move internals are unread. This load route can request file mutation. (P019-07)

Unread helper 015ea7b8 receives `(originalBundleURL,&zeroInitializedFlag,activeVariant)`. Its **actual returned URL** is preserved and supplies the later data-loader argument; misleading decompiled C appears to reuse the original URL. A nonzero flag restores old information and returns false, storing Cocoa3072 only when `errorOut` is non-NULL. With flag 0, a nil returned URL instead restores information and uses Cocoa259. Helper selection, flag semantics and runtime URL type are unknown. (P019-08)

A nonnil returned URL is passed to `setDocumentFileDataFromURL:usedAutoSave:error:` with a stack-byte output address and `errorOut`. Its actual result is retained; a zero success bit restores old information before returning. **The caller does not initialize the `usedAutoSave` byte**, so interpretation depends on callee output. The native data-loader body and native `ProjectData` parser remain unread. (P019-09)

After data success, the wrapper ORs bit0 into the byte at the returned song pointer+0x94; that field's meaning is unknown. A set low `usedAutoSave` bit skips display reading and setting. Otherwise, it obtains `displayStateArchiveURL` and `oldDisplayStateURL(createDirectories=false)`, reads with options0 and a local error, and falls back to the old URL only when the first data result is nil. The actual selected or fallback data is sent to **`setDisplayFileData:`**, even if both reads returned nil: there is no caller nil gate. The actual branch target resolves to this selector rather than the C label `func_0x01c77778`. Display errors are not stored to original `errorOut` and do not override the data-loader success result. The song field, actual autosave objects, display setter internals and live state are unverified. (P019-10–11)

The successful tail requests removal of `originalBundleURL/tmp` with errorNULL and ignores the result. Only when the original `mAlternativeToLoad` was not −1 does it call `_writeProjectInformation:error:` with the original URL and local error; that result is also unchecked. It returns the saved data-loader result. Thus successful wrapper return does not prove successful cleanup, metadata writing, a side-effect-free open or a save/reload/Undo roundtrip. (P019-12)
