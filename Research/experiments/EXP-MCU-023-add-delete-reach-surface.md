# EXP-MCU-023: トラックの追加・削除は MCU の表示に届くか（と、削除後に古いバンク位置を信じる不具合）

| 項目 | 内容 |
|---|---|
| 日時 | 2026-10-02 14:00–14:40 JST |
| Logic バージョン | 12.3.1 (6682) |
| macOS バージョン | 27.0 (26A5416b) |
| Logic Remote バージョン | 該当なし |
| テストプロジェクト | LogicCLI-Test.logicx（トラック10 + St Out + Master = 12ストリップ）。保存はしていない |
| ツール | `logicctl`（`--expect-name`）、`logicctl status` の `mcu_lcd`（LCD の写し。バンクを動かさない）、Logic のメニュー操作 |
| 初期状態 | MCU に接続済み。トラックはすべてミュート解除 |
| 1つの操作 | 実験 A：メニュー「トラック → 新規オーディオトラック」。実験 B：メニュー「トラック → トラックを削除」（追加したトラックを選択中） |
| 再現回数 | 追加と削除を 2 サイクル（1 回目は旧ビルド、2 回目は修正後のビルド） |

## 観察

### 実験 A：トラックの追加（1 サイクル目）

| 段階 | 観察 |
|---|---|
| 追加前の LCD | `Piano  Audio  Bass   Synth  Trk05  Trk06  Trk07  Trk08  `（バンクの先頭） |
| 追加直後の LCD（バンクはこちらから動かしていない） | `Trk05  Trk06  8      Trk07  Trk08  Trk09  Trk10  St Out ` |
| 照合（追加前の配置で） | トラック 7 に `Trk07`、11 に `St Out`、12 に `Master` を期待 → **3 件とも `target_mismatch`**（実際は `8`、`Trk10`、`St Out`） |
| `track list` | 完全。13 ストリップ |

- Logic は追加を表面に反映した。**表示範囲（バンク）も Logic 自身が動かした**（先頭が `Piano` から `Trk05` に変わった）。
- 新しいトラックの名前は Logic 上で「オーディオ 8」。LCD では **`8`** と出る。非 ASCII の文字は表示されなかった（1 例）。

### 実験 B：トラックの削除（1 サイクル目、修正前のビルド）

| 段階 | 観察 |
|---|---|
| 削除前の LCD | `Trk06  8      Trk07  Trk08  Trk09  Trk10  St Out Master `（トラック 6〜13。バンク位置 5） |
| 削除直後の LCD | `Trk05  Trk06  Trk07  Trk08  Trk09  Trk10  St Out Master `（トラック 5〜12。バンクが詰められた） |
| `track get 13 --expect-name Master` | **成功（不具合）**。存在しないトラック 13 が `Master` として読めた |
| `track get 8 --expect-name Trk07` | **成功（不具合）**。トラック 8 は `Trk08` のはずが、`Trk07` を読んだ |
| `track list` | 完全。12 ストリップ（正しい） |

- 表示は更新されていたが、`logicd` は削除前のバンク位置（5）を信じたまま、表示の別のセルを読んでいた。

### 不具合の原因（Hypothesis）

仮説（Hypothesis）: 削除でバンクが詰められたとき、Logic は名前行を書き直すが、バンク移動を知らせる色の sysex は送らない。
確信度: 高。根拠は、`bankIsKnown`（色の更新回数と接続の世代が、位置を決めたときと同じか）が真のままだったこと。のちに MIDI を記録し、削除の直後に色の sysex が届かないことを確かめた（[EXP-MCU-024](EXP-MCU-024-trace-add-delete.md)）。
`logicd` はバンクの移動を色の sysex の回数で検知していた（EXP-MCU-020）。ボタンによる移動では 1 回ずつ届くが、削除による詰めでは届かなかったと推定する。

### 修正と再確認（2 サイクル目、修正後のビルド）

- `MCUBackend`：位置を決めたときの名前行（上段 LCD）を覚え、**表示がそれと変わったら位置を信じず、先頭から位置を取り直す**。
- 単体試験：`aBankShiftWithoutAColourSignalIsStillNoticed`（色の信号なしでバンクが詰められる模擬）。修正前は失敗し、修正後は通る。
- 実機：追加 →（`track get 13 --expect-name Master` で末尾に位置合わせ）→ 削除。結果：

| 確認 | 結果 |
|---|---|
| 削除直後の LCD | `Trk05  Trk06  Trk07  Trk08  Trk09  Trk10  St Out Master ` |
| `track get 13` | **`no_such_track`**（修正前は `Master` を返していた） |
| `track get 8 --expect-name Trk08` | 成功 |
| `track get 8 --expect-name Trk07` | `target_mismatch`（実際は `Trk08`） |
| `track get 12 --expect-name Master` | 成功 |
| `track list` | 完全。12 ストリップ、名前はすべて元どおり |

## 並べ替え（未確認）

並べ替えは起こせなかったため、**結果は無い**。

- トラックヘッダーのドラッグ（バックグラウンド操作、アイコンの位置から）：トラックが選択されただけで、並びは変わらなかった。
- メニュー「トラック → トラックを並べ替える → トラック名」（バックグラウンド操作）：実行したが、並びも LCD も変わらなかった。
- 後日の再試行（画面を前面にした実際のマウス操作）：ボタンの位置から始めたドラッグは、トラックのミュート（`M`）を入れただけだった（元に戻した）。
  トラック番号、アイコン、ボタンの間の空きからゆっくり動かしたドラッグ（3 通り）は、いずれも選択になっただけだった。
  メニュー「トラック名」を実際のクリックで実行しても（1 本選択、10 本選択の 2 回）、変化は無かった。Logic の取り消し履歴にも「並べ替え」は記録されていない（名称変更 2、トラックを作成 3、トラックを削除 3 のみ）。
- したがって、**この操作方法では並べ替えが起きない**。Logic の挙動なのか、入力の送り方（合成されたマウス操作）の制約なのかは区別できていない。

## その他の観察

- `handshake_generation` は、この間に 4 から 8 になった。こちらの操作に対応しない時刻（05:22 UTC）に、Logic が接続要求を繰り返した。原因は未調査。

## 仮説（Hypothesis）

仮説（Hypothesis）: Logic は、トラックの追加・削除でストリップの並びが変わると、MCU の名前行を書き直す。ただし、バンクの移動を示す色の sysex を伴うとは限らない。
確信度: 追加・削除の反映は高（実機で 2 回ずつ、LCD の写しと照合結果が一致）。色の sysex の欠落は中（上記）。
反例: なし。
次の検証実験: (1) 〔済〕削除時の MIDI の記録：[EXP-MCU-024](EXP-MCU-024-trace-add-delete.md)。
(2) 並べ替え：人の手による操作、またはキーコマンド（ここまでの合成マウス操作では起こせていない）。(3) 名前行を使う位置の再取得が、実際の使用で過剰な再位置合わせを起こさないかを見る。

## logicctl への帰結

- 追加・削除は、`--expect-name` で検出できた（実機）。並べ替えは未確認のまま。
- バンク位置は、色の更新回数・接続の世代に加えて**名前行が変わっていないこと**も条件にした。
- Logic は追加のとき、表示範囲を自分で動かすことがある。`track list` の走査は、これまでと同じく先頭から取り直す。
- 非 ASCII の名前は LCD に出ないことがあり、`name` は元の名前と一致しない。照合には、表示された `name` をそのまま使う。
