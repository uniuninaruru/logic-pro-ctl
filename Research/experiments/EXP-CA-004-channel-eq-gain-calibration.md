- O1：順 2〜8 の 7 点は、予測と一致した（表示は 0.1 dB 刻み）。順 7・8 は、式から先に予測してから送った。
- O2：**−6.0 dB ちょうどは、1 回の 7 ビットの CC では出せない**。刻みは約 0.378 dB で、最も近いのは 48（−5.9 dB）と 47（−6.2 dB）。
- O3：順 1 の 64 は無視された（表示は 0.0 dB のまま）。直前に同じ対象へ送った最後の値は 64 で、対象の値は 0.0 dB（CC では 63.5 に当たる）。次の 127 は反映された（64 → 127 は 63.5 をまたぐ）。ピックアップの「またぐ」で同期する、という [EXP-CA-003](EXP-CA-003-value-mode-pickup-ab.md) の結論と合う。
- O4（検証の段階）：①MIDI の送信：`probe8.log` に送信 8 通（確認済み）。②Logic への割り当て：コントローラアサインメントの行 CC 23 を画面で確認済み（今回は再読していない）。③変更後の値：**画面の表示だけ**で確認（アクセシビリティの値としては未確認）。
- 生データ（Git の対象外）：`Research/raw/midi-learn/probe8.log`。画面の読み取りは操作時刻と一緒に会話の記録に残した。

## 仮説（Hypothesis）

仮説 H1：Channel EQ の Master Gain への CC 23 は、表示が 0.1 dB の範囲で、−24 + 値 × 48 / 127 dB に従う。確信度：高（7 点が予測と一致）。
H2：「目標の dB から、最も近い CC の値を選び、読み戻して確認する」閉じた手順で、±0.2 dB 程度の精度が得られる。確信度：中（このプラグインの 1 パラメーターだけ）。
H3：正確な値の確認には、画面の拡大でなく、アクセシビリティから読める値が要る（RDCO の調査を待つ）。確信度：該当なし。
